# Tinix 分模块演示说明

这套材料用于明天中期答辩时按模块演示 Tinix 的四个核心功能：文件系统、进程管理、设备管理、内存管理。

## 1. 演示前准备

建议在仓库根目录执行，先完成构建：

```bash
cmake -S . -B build
cmake --build build
./build/tinix
```

进入 Shell 后，按下面四个模块依次演示即可：

```bash
script demo/01_fs_demo.tsh
script demo/02_process_demo.tsh
script demo/03_device_demo.tsh
script demo/04_memory_demo.tsh
```

如果担心旧的 `disk.img` 干扰演示，最稳的方式是在一个新目录中运行可执行文件，并把 `demo/` 目录整体复制过去。

## 2. 推荐演示顺序

1. 文件系统
2. 进程管理
3. 设备管理
4. 内存管理

这个顺序从最直观的功能开始，再逐步过渡到调度、阻塞和页面置换，老师更容易跟上。

## 3. 模块一：文件系统

运行：

```bash
script demo/01_fs_demo.tsh
```

脚本内容：

- `format`
- `mount`
- `mkdir /demo`
- `touch /demo/msg`
- `echo hello > /demo/msg`
- `cat /demo/msg`
- `cd /demo`
- `pwd`
- `fsinfo`

你要重点指出：

- 文件系统支持格式化和挂载
- 可以创建目录和普通文件
- 可以完成写入和读取
- `fsinfo` 能看到超级块信息，说明文件系统状态确实落在磁盘镜像里

建议口播：

“这一部分演示的是基于 inode 的简化文件系统。先格式化并挂载，再创建目录和文件，写入 `hello` 后立刻读出，说明基本文件操作是通的。最后通过 `fsinfo` 展示超级块元数据，说明这不是一次性的内存结构，而是有持久化后端的。” 

如果老师追问“怎么证明持久化”，你可以退出后重新启动，再执行：

```bash
mount
cat /demo/msg
```

## 4. 模块二：进程管理

运行：

```bash
script demo/02_process_demo.tsh
```

脚本分两段。

第一段展示时间片轮转：

- 创建两个纯计算进程
- 先 `ps`
- `tick 3`
- 再 `ps`
- 再 `tick 3`
- 再 `ps`

你要重点指出：

- 系统使用时间片轮转调度
- 一个进程时间片用完后会回到就绪队列
- 另一个进程会接替执行

建议口播：

“这里我先创建两个纯计算进程。系统的默认时间片长度是 3，所以每执行 3 个 tick，当前进程会让出 CPU，另一个进程开始运行。这体现的是最基本的 Round-Robin 调度机制。”

第二段展示阻塞与自动唤醒：

- 先结束前面两个纯计算进程，避免它们继续占用调度
- 创建 `demo/process_sleep.pc`
- 执行 `tick 2`
- 查看 `ps`
- 再执行 `tick 3`
- 再查看 `ps`

你要重点指出：

- 脚本中的 `S 3` 会让进程进入阻塞态
- 阻塞时间到期后会自动回到就绪态

建议口播：

“第二段我用一个很短的 `Sleep` 脚本来演示阻塞和唤醒。进程执行到 `S 3` 时会立即进入 Blocked，阻塞计时结束后由系统自动唤醒并重新参与调度。”

## 5. 模块三：设备管理

运行：

```bash
script demo/03_device_demo.tsh
```

脚本内容：

- 创建两个相同的设备请求进程
- 先 `dev`
- `tick 1`
- 再 `dev`
- `tick 10`
- 再 `dev`

你要重点指出：

- 第一个进程先拿到设备
- 第二个进程因为设备忙而进入等待队列
- 当前一个进程释放设备后，等待队首会被唤醒

建议口播：

“这一部分展示设备申请、排队和释放唤醒。两个进程请求同一个设备，前一个会立刻获得设备，后一个进入 FIFO 等待队列。等前一个执行 `DD 0` 释放设备后，设备会转交给队首进程，并把它从阻塞态唤醒。”

你可以提醒老师关注这几类日志：

- `Granted`
- `Queued`
- `Wakeup`

## 6. 模块四：内存管理

运行：

```bash
script demo/04_memory_demo.tsh
```

脚本内容：

- 创建 `demo/memory_intensive.pc`
- `tick 8`
- `mem`
- `tick 1`
- `mem`
- `tick 7`
- `memstats`

你要重点指出：

- 系统物理内存只有 8 个页框
- 前 8 次访问主要是分配页框
- 第 9 次访问开始没有空闲页框，会触发缺页和页面置换
- 最后可以看到缺页统计结果

建议口播：

“这里的内存管理采用分页模型，物理内存页框数固定为 8。这个脚本会连续访问 16 个虚页，所以前 8 页只是装入物理内存，第 9 页开始就必须触发缺页处理和 Clock 页面置换。日志里能看到 `PageFault`、`Evict` 和 `Swap Writing`，最后 `memstats` 会给出统计结果。”

你可以提醒老师关注这几类日志：

- `[PageFault]`
- `[Evict]`
- `[Swap] Writing`

## 7. 如果时间不够

如果老师只给你很短时间，不要分开敲很多命令，直接运行仓库根目录现成的总脚本：

```bash
script demo_acceptance.tsh
```

这条脚本会一次性串起：

- 文件系统
- `.pc` 文件驱动的文件操作
- 设备请求与唤醒
- 缺页与页面置换

## 8. 收尾怎么说

演示结束后建议用两句话收尾：

“Tinix 的定位是用户态教学模拟器，不追求真实内核的全部复杂度，而是强调机制正确、链路贯通和状态可观测。”

“当前四个核心模块已经打通，而且支持脚本化复现，适合课程验收和后续继续扩展。”
